# GAS 在庫・買取台帳 自動化サンプル

> **自主制作サンプルです。** 実際の案件・納品物ではありません。
> 店舗名・商品・金額などのデータはすべて架空です。
>
> 公開場所：https://github.com/wraiser/portfolio/tree/main/gas-inventory-automation （ポートフォリオ https://wraiser.github.io/portfolio/ の作品の1つ）

リユース・買取店を想定し、Google スプレッドシートで管理する「買取台帳」の入力チェック、滞留在庫の見える化、日次集計、通知を Google Apps Script（GAS）で自動化したサンプルです。

## 想定した課題

買取・リユース業では、スプレッドシートで買取台帳を管理している店舗が多くあります。手作業の運用では、次のような問題が起こりがちです。

- 管理番号の重複や、販売済なのに販売価格が空欄といった入力ミスに気づきにくい
- 買取から日数が経った在庫（滞留在庫）を探すのに手間がかかる
- 日々の買取・販売・在庫金額の集計を、毎日手作業で作っている
- 行数が増えると、スクリプトが実行時間の上限（6分）で止まる

## 機能

| 機能 | 内容 | 関数 |
| --- | --- | --- |
| 初期設定 | 台帳とエラーログのシートを作成。プルダウン（ステータス・カテゴリ・状態ランク）と表示形式を設定。既存データは消さず、足りない列だけ追加 | `setupSheets` |
| 入力チェック（自動） | 編集した行だけをその場で検証し、「検証結果」「更新日時」を記入。エラーのあるセルは赤 | `onEdit` |
| 入力チェック（全件） | 全行を検証し、管理番号の重複も検出 | `validateAll` |
| 滞留日数の計算と色付け | 在庫・出品中の商品について、買取日からの日数を計算し、30日・60日・90日以上で行の色を変える | `updateStagnation` |
| 日次集計シート | 前日の買取・販売（売上・粗利）、在庫件数と金額、滞留区分別、カテゴリ別、店舗別を集計し、`日次集計_yyyyMMdd` シートを作成。古いシートは14日分を残して削除 | `createDailySummary` |
| 通知 | 日次集計の要約と、滞留日数の長い在庫の上位10件を Slack とメールに送信 | `sendDailyNotification_` |
| トリガー設定 | 毎朝6時台に「滞留日数の更新 → 日次集計 → 通知」を実行するトリガーを設定・削除 | `setupTriggers` / `removeTriggers` |
| エラーログ | 失敗した処理名・メッセージ・スタックを「エラーログ」シートに記録（最大1,000行） | `logError_` |

スプレッドシートを開くと、メニューに「在庫自動化」が追加され、上の処理を手動でも実行できます。

## シート構成

### 買取台帳

| 列 | 入力 | 内容 |
| --- | --- | --- |
| 管理番号 | 手入力 | 例: `OS-00001`（英大文字2桁＋ハイフン＋数字5桁） |
| 買取日 | 手入力 | 未来の日付は不可 |
| 店舗 | 手入力 | |
| カテゴリ | プルダウン | ブランドバッグ／時計／貴金属／カメラ／家電／ゲーム／衣類／その他 |
| 商品名 | 手入力 | |
| 状態ランク | プルダウン | S／A／B／C／D |
| 買取価格 | 手入力 | 0以上の整数 |
| 販売予定価格 | 手入力 | |
| ステータス | プルダウン | 在庫／出品中／販売済／廃棄 |
| 販売日 | 手入力 | 販売済のときは必須。買取日より前は不可 |
| 販売価格 | 手入力 | 販売済のときは必須 |
| 滞留日数 | 自動 | 在庫・出品中のみ |
| 検証結果 | 自動 | `OK` またはエラー内容 |
| 更新日時 | 自動 | 最後に編集された日時 |

### その他のシート

- **日次集計_yyyyMMdd**：日次ジョブが毎日作成
- **エラーログ**：日時・処理・メッセージ・詳細

## ファイル構成

```
gas-inventory-automation/
├─ src/
│  ├─ appsscript.json    マニフェスト（タイムゾーン Asia/Tokyo、V8）
│  ├─ Config.gs          シート名・列名・しきい値などの設定
│  ├─ Logic.gs           検証・日数計算・集計などの純粋関数（GAS API を使わない）
│  └─ Main.gs            シートの読み書き、トリガー、通知、エラーログ
├─ tests/
│  ├─ logic.test.js      Logic.gs の単体テスト
│  └─ main.smoke.test.js GAS API をモックにした Main.gs の動作確認
├─ sample-data/
│  └─ purchase_ledger_sample.csv  架空の台帳データ（40件）
├─ .clasp.json.example
└─ package.json
```

## セットアップ

### A. エディタに貼り付ける場合

1. 新しい Google スプレッドシートを作成し、「拡張機能 → Apps Script」を開く
2. `Config.gs`、`Logic.gs`、`Main.gs` を同じ名前で作成して内容を貼り付ける
3. 「プロジェクトの設定」で「appsscript.json マニフェスト ファイルをエディタで表示する」をオンにし、`src/appsscript.json` の内容に置き換える
4. スプレッドシートを再読み込みし、メニュー「在庫自動化 → ① 初期設定」を実行（初回は権限の承認が必要）
5. 「買取台帳」シートの A1 セルを選択し、「ファイル → インポート」で `sample-data/purchase_ledger_sample.csv` を「選択したセルを置換」で読み込む（CSV の1行目は台帳と同じ見出しです）
6. 「② 全件を検証」「③ 滞留日数を更新」「④ 日次集計を作成」で動作を確認する

### B. clasp を使う場合

```bash
git clone https://github.com/wraiser/portfolio.git
cd portfolio/gas-inventory-automation
npm install -g @google/clasp
clasp login
cp .clasp.json.example .clasp.json   # scriptId を自分のプロジェクトのIDに書き換える
clasp push
```

### 通知先の設定（任意）

URL とメールアドレスはコードに書かず、「プロジェクトの設定 → スクリプト プロパティ」に登録します。設定しなかった通知先は送信を飛ばします。

| プロパティ | 値の例 |
| --- | --- |
| `SLACK_WEBHOOK_URL` | Slack の Incoming Webhook URL |
| `NOTIFY_EMAIL` | 通知を受け取るメールアドレス |

設定後、メニューの「通知のテスト送信」で確認できます。

### 毎日の自動実行

メニューの「日次ジョブのトリガーを設定」を実行すると、毎朝6時台に `runDailyJob` が動きます。時刻は `Config.gs` の `DAILY_TRIGGER_HOUR` で変更できます。

## 設計上の工夫

### 保守性

- **列を見出し名で参照**：列番号を直接書かず、見出し行から対応表を作ります。列の並び替えや追加をしても処理が壊れにくく、必要な見出しがない場合は不足している見出し名をエラーで示します。
- **設定を1ファイルに集約**：シート名、選択肢、滞留日数のしきい値、色、バッチサイズなどは `Config.gs` だけで変更できます。
- **計算と入出力を分離**：検証・日数計算・集計は `Logic.gs` の純粋関数にまとめ、シートの読み書きは `Main.gs` に限定しました。業務ルールの変更はロジック側だけで済み、Node.js でテストできます。

### エラー処理

- 失敗した処理は「エラーログ」シートに記録し、ログの書き込み自体が失敗しても処理全体は止めません。
- 日次ジョブは「滞留日数の更新」「日次集計」「通知」を個別に実行し、1つが失敗しても次へ進みます。
- Slack 送信は 429・5xx のときだけ待ち時間を延ばしながら再試行し（最大3回）、400 などは再試行せず記録します。Slack が失敗してもメールは送ります。
- `LockService` で同じ処理が同時に動かないようにしています。
- 入力ミスは「検証結果」列に内容を書き、集計からは外して「要確認」の件数として示します。

### パフォーマンス

- セルを1つずつ読み書きせず、`getValues` / `setValues` / `setBackgrounds` で範囲ごとにまとめて処理します。
- 滞留日数の更新は500行ずつ進め、開始から4分30秒を過ぎたら処理位置をスクリプトプロパティに保存し、1分後に続きを実行するトリガーを予約します。最後まで終わったら、保存した位置と予約したトリガーを削除します。
- `onEdit` は編集された行だけを検証します（重複チェックのため、管理番号の列だけは全行を読みます）。

## テスト

```bash
cd gas-inventory-automation   # リポジトリ直下から移動する場合
npm test
```

- `tests/logic.test.js`：日付の解釈、日数計算、入力チェック、集計、バッチの分割、再試行の待ち時間などの単体テスト
- `tests/main.smoke.test.js`：SpreadsheetApp などを簡易モックに置き換え、全件検証、バッチの中断と再開、日次ジョブ、Slack の再試行、`onEdit` を確認

モックによる確認のため、実際の Apps Script 環境での権限承認・実行時間・トリガーの発火までは再現していません。

## 注意事項

- このフォルダ（`gas-inventory-automation/`）は技術サンプルとして作成したもので、特定の企業・店舗の業務や実データとは関係ありません。
- `sample-data/purchase_ledger_sample.csv` は架空データです。検証機能の確認用に、入力ミスを含む行を2件入れています（`OS-00039`：買取価格が空欄、`os-40`：管理番号の形式誤り）。
- サンプルデータの日付は 2026年11月5日 を基準に作成しています。実行日によって滞留日数や前日の集計結果は変わります。
